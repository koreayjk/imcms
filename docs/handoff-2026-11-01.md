## 보도자료 → AI 기사 자동 작성 (이번에 만든 것)
- 구성: `lib/auto-press.ts`(본 로직), `lib/commons-photo.ts`(위키미디어 사진 검색), `app/api/cron/auto-articles/route.ts`, `supabase/auto-press-articles.sql`(운영 DB에 이미 적용). 작업서에도 요약이 있다.
- 동작: 8개 매체마다 매시간 정각에 서버를 깨운다(Supabase 예약 작업 `auto-press-articles`). 서버가 미국 중부 0~8시이고 오늘 5건 미만일 때만 기사 1건을 만든다. 흐름은 보도자료 선택 → AI 기사 → AI 법적 검수(지적 문장 자동 수정) → 사진 → **승인 대기(in_review)** 저장.
- 사진: 보도자료 사진이 있으면 그것을, 없으면 키워드로 위키미디어 공용 → Openverse 순으로 찾고, 안 나오면 일반 검색어로 넓힌다. 그래도 없으면 그 보도자료는 건너뛴다. 사진은 원본 주소를 그대로 연결한다(원본이 지워지면 깨질 수 있음).
- 설정·기록: 테이블 `auto_press_outlets`(켜기/끄기, 하루 건수, 시간대, 기자명), `auto_press_log`(성공·실패 이유·비용). 끄기 `update auto_press_outlets set enabled=false where outlet_id='...'`, 전체 중지 `select cron.unschedule('auto-press-articles')`.
- 시험으로 만든 기사: Breaking BCS "Texas A&M Wins $5.4M Federal Grant…", 에듀와이드 "편한 공부는 효과 없다…" (둘 다 승인 대기).
- 비용: AI 키(Gemini/Anthropic) API 비용. 하루 40건이면 약 $0.2~0.5 추정. 요금제별 AI 사용 한도 집계에는 잡히지 않는다(필요하면 한도에 포함되게 바꿀 수 있음).

## 지자체 보도자료 수집 (2026-11-03 시작)
- 코드: `lib/press-local.ts`(안산시·경기도뉴스포털 게시판 읽기), `lib/press-sources.ts`의 `lg-*` 출처 3개(`lg-ansan`, `lg-gg-sigun`, `lg-gg-do`), `lib/press.ts`의 `kind: 'gov'` 처리.
- 경기도뉴스포털(gnews.gg.go.kr)의 "시군 보도자료"는 지금 글을 올리는 시군(첫 화면에는 양주·포천 등)만 나온다. `?bm_name=시군이름`으로 시군별 목록을 볼 수 있는데, 화성·평택·안산은 최신 글이 2008~2013년이라 이 경로로는 쓸 수 없다. 경기도 본청(gg.go.kr)은 해외·서버 접속을 보안 정책으로 막는다. RSS는 인증키가 필요해 쓰지 않는다.
- 평택시: 목록은 `/pyeongtaek/board/post/list.do?bcIdx=90&mid=0402010000` 에서 읽힌다(제목·날짜·요약, 글 번호 `data-req-get-p-idx`). 상세는 GET이 400이라 폼 전송(POST, yhLib.inline.post)을 풀어야 한다. 수집기는 목록까지만 있다(`lg-pyeongtaek`, 제목·날짜·요약만 쌓고 본문·사진은 못 가져온다).
- 화성시: 접속 대기열(NetFunnel)이 있고 보도자료 게시판 주소를 아직 못 찾았다. 수집기 없음. 대기열을 우회하는 방식은 쓰지 않는다.
- 이 출처로 기사를 쓰려면 매체의 `require_words`(`auto_press_outlets`)에 지역 단어가 맞아야 한다. 뉴스폭탄은 아직 자동 작성 대상이 아니다.
