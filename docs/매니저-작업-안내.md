## 1. 기본 원칙 (어기지 않는다)

- **내 담당 언론사만 건드린다.** 다른 매체의 기사·설정·사진은 읽기만 해도 먼저 이유를 말한다. 운영 DB는 모든 매체가 함께 쓰므로 `where outlet_id = '<내 매체 id>'`를 빠뜨리지 않는다.
- **사용자가 시키지 않은 일은 시작하지 않는다.** 답은 한국어, 짧고 쉬운 말로. 모르는 것은 "확인 못 했다"고 쓴다.
- **쓰기 전에 읽는다.** 대상과 현재 값을 `select`로 보고, 몇 건이 바뀌는지 말한 뒤 쓴다. 같은 SQL을 다시 실행해도 중복되지 않게 쓴다 (`legacy_id`, `press_release_id` 등으로 `where not exists`).
- **삭제(`delete`·`drop`·`truncate`), 많은 행을 바꾸는 `update`, 구조 변경(`apply_migration`)은 사용자에게 무엇을 몇 건 바꾸는지 먼저 말하고 허락받은 뒤에 한다.** 삭제는 되돌릴 수 없다.
- **비밀값을 채팅·커밋·문서에 쓰지 않는다.** Supabase `service_role` 키, Resend·Vercel 키, 도메인 인증코드, 고객 개인정보(전화·주소)가 해당한다. 키가 필요한 일은 사용자 컴퓨터에서 환경변수로 실행하는 스크립트로 만든다 (예: `scripts/migrate-chunghyup-images.mjs`).
- **AI가 올리는 기사는 발행하지 않는다.** `status = 'in_review'`(승인대기), `published_at`은 비운다. 발행은 그 매체 편집장이 한다.
- **다른 프로젝트의 DB는 읽지도 쓰지도 않는다.** 운영 DB는 Supabase 프로젝트 `imcms` (id `xmkrpjsetdneulyyasrf`) 하나뿐이다.

## 2. 도구와 접속

- DB는 `mcp__Supabase__execute_sql`로 직접 읽고 쓴다 (`.claude/settings.json`이 이 호출을 묻지 않고 허용). (`docs/launch-runbook.md`에 "DB에 직접 접속하지 못한다"는 예전 문장이 남아 있으나 지금은 위 도구로 접속한다.) 이 도구가 보이지 않는 창이라면 **SQL 파일을 `supabase/`에 만들고 사용자에게 실행을 요청**한다. 파일 이름과 실행 순서를 알려 준다.
- 삭제·구조 변경 같은 쓰기에서 Supabase가 확인 창을 띄우면 사용자가 허용해야 한다. 2분 안에 답이 없으면 만료되니 사용자에게 알리고 기다린다. 같은 호출을 연달아 반복하지 않는다.
- GitHub는 MCP 도구(`mcp__github__*`)로 PR을 만들고 합친다. 빌드 상태는 PR의 Vercel 상태로 본다.
- 사용자 컴퓨터가 필요한 일(큰 파일 업로드, DNS, 지메일 설정)은 따라 할 명령을 한 단계씩 쓴다. 운영체제(맥/윈도)를 먼저 확인한다.

## 3. 브랜치·배포·PR 규칙 (창이 여러 개라서 중요)

- **창마다 자기 브랜치를 쓴다.** 이름 예: `claude/<매니저>-<매체>-<주제>`. 다른 창의 브랜치에 푸시하지 않는다. 같은 파일을 두 창이 동시에 고치지 않는다.
- 작업 시작: `git fetch origin claude/new-session-tdsge1` 후 그 위에서 브랜치를 만든다 (기준 브랜치 = `claude/new-session-tdsge1`, 여기가 운영 배포 기준).
- 푸시 전: `npx tsc --noEmit -p .`가 통과해야 한다. 실패하면 푸시하지 않는다.
- 커밋 메시지는 한국어로 짧게, 끝에 안내된 `Co-Authored-By` 줄을 붙인다.
- **PR은 사용자가 요청할 때만 만든다. 머지는 사용자가 "머지해줘"라고 할 때만 한다.** 머지 전에 Vercel 빌드가 성공인지 확인한다 (진행 중이면 끝날 때까지 기다린다).
- 머지된 브랜치에 새 커밋을 쌓지 않는다. 기준 브랜치의 최신에서 다시 시작한다.
- `sleep`으로 기다리지 말고, 상태를 반복 조회하거나 모니터링 도구를 쓴다.
- **공용 코드(`lib/`, `components/`, `app/`)를 고치는 일은 담당자 한 명이 하도록 사용자에게 먼저 묻는다.** 매체 하나만의 설정·기사·섹션·사진은 데이터 작업이라 각 창에서 해도 된다.

## 5. 매체 하나를 다룰 때 알아야 할 구조

- 매체: `outlets` (설정은 `site` jsonb: 로고·색·`lang`·`aiNotice`·`pressTiers`·`mailSections` 등). **`site`는 키 한 개만 바꾸는 전용 함수로 저장한다** (`outlet_site_self_save`는 보내지 않은 키를 지우므로, 보도자료 그룹은 `outlet_press_tiers_save`, 메일 섹션은 `outlet_mail_sections_save`로만 바꾼다).
- 섹션: `categories` (`outlet_id`, `name`, `slug`, `sort_order`). 기사에는 `articles.category_id`.
- 기사: `articles` — 주요 열 `outlet_id, category_id, author_id(필수), byline, title, body(html), excerpt, tags(text[]), thumbnail_url, status, published_at, legacy_id, press_release_id, ai_notes`.
  - 상태: `draft` / `in_review`(승인대기) / `published` / `rejected`.
  - `legacy_id`는 옛 사이트 기사 번호. (매체, 번호)가 유일해서 같은 파일을 다시 가져와도 건너뛴다. 옛 주소 → 새 기사 연결에 쓴다.
- 사진: 저장소 버킷 `media`, 경로 `<매체id>/…`. **파일당 10MB 한도**, 형식 jpeg·png·webp·gif. 매체별 용량(베이직 30GB 등)은 사진+영상 합계(`outlet_storage_bytes`). 보도자료함 글·메일 첨부는 이 용량에 들어가지 않는다.
- 기사 본문 표시: 서버가 본문 HTML을 한 번 정리한다(`lib/article-html.ts`) — **`class`·대부분의 `style`은 지워진다.** 서식은 CSS(`app/globals.css`의 `.article-content`)로 준다.
- 기자명: **그 매체 편집장 이름**으로 쓴다 (`CLAUDE.md`). `articles.byline`과 본문 첫머리 `[매체이름=편집장이름 기자]`. 모르면 만들기 전에 사용자에게 묻는다. 이전한 기사는 원래 기자명을 그대로 두고, 옛 매체 이름이 들어간 것만 새 이름으로 바꾼다.

## 6. 자주 하는 일 (조회 먼저, 쓰기는 허락 후)

```sql
-- 내 매체 기사 수·상태
select status, count(*) from articles where outlet_id = '<매체id>' group by 1;
-- 섹션별 기사 수
select coalesce(c.name,'(없음)') as 섹션, count(*) from articles a left join categories c on c.id = a.category_id where a.outlet_id = '<매체id>' group by 1 order by 2 desc;
-- 승인대기 기사
select id, left(title,40), byline, created_at from articles where outlet_id = '<매체id>' and status = 'in_review' order by created_at desc;
-- 저장소 용량
select * from outlet_storage_bytes('<매체id>');
```

- **AI 기사 만들기(시작용 기사 포함)**: 보도자료는 목록에 요약만 있다. **원문 페이지를 읽고 쓴다.** 직접 인용 대신 요약, 사진은 사용 권리를 모르면 넣지 않는다. `ai_notes`에 출처·원문 주소·확인할 점을 남기고, 매체 설정(`site.aiNotice`)이 켜져 있으면 본문 끝에 AI 활용 표시를 넣는다. 법적 검수 기록을 남긴다면 "AI 점검, 법률 자문 아님"으로 밝힌다. 소재가 모자라면 건수를 억지로 채우지 않는다.
- **섹션 만들기·정리**: `supabase/<이름>-sections.sql` 패턴. 옛 사이트와 같은 이름·순서로 맞춘다.
- **기사·사진 이전**: `docs/migration-runbook.md`. 도구는 총관리자 화면 `/admin/import` (JSON·CSV·MySQL 백업을 읽음). 큰 사진 묶음은 사용자 컴퓨터에서 `scripts/migrate-chunghyup-images.mjs`(옵션 `--legacy`, `--local`, `--dry`) 방식으로 올리고, 본문 속 사진 주소는 새 저장소 주소로 바꾼다. 옛 `/news/photo/…` 같은 상대 주소는 올린 뒤 SQL로 바꾼다 (건수를 먼저 보여주고 허락받는다).
- **기사 목록에서 본 것과 DB가 다르면** 먼저 `status`, `published_at`(미래 시각이면 공개 전), 매체 "오픈 준비 중" 설정을 본다.

## 7. 보도자료함·메일 수신 (매체 담당자가 자주 묻는 부분)

- **보도자료함** `/press`: 지자체·뉴스와이어·해외 언론 자료를 30분마다 수집. 화면은 **기본으로 최근 7일**, **이미 우리 매체가 기사로 쓴 자료는 숨김**("지난 자료까지 보기"로 다시 볼 수 있음).
- **품질 판정**: 글이 충분(한국어 300자·영문 150단어)하고 사진이 있는 자료만 목록에 보인다 (`press_releases.quality = 'ok'`). 5분마다 `/api/cron/press-quality`가 상세 페이지를 읽어 판정한다. 해외 언론(미국 제외)은 사진 조건 없음. 직접 등록·메일 자료는 판정하지 않는다. 판정이 밀려 있으면 목록이 비어 보일 수 있다 (`select quality, count(*) from press_releases group by 1`).
- **맞춤 자료**: 설정은 전체 탭에서만 한다 (그룹 1~4, 키워드, 출처). 맞춤 탭은 보기 전용. 저장은 `outlet_press_tiers_save`. 뉴스와이어 통과 자료는 항상 위에 둔다.
- **일괄 AI 기사**: 보도자료 체크 → 분량(자동/800/1,000/1,500자) → 승인대기로 보냄. 섹션은 AI가 매체 섹션 중에서 골라 `ai_notes`에 적는다. 편집장이 승인 전에 바꾼다.
- **메일로 받기**: 기자마다 전용 주소 `press+토큰@…` (Resend 수신). 기자 지메일 **전달 필터**로 보도자료 메일만 넘기게 한다. (받은편지함 전체를 넘기면 광고·서비스 알림이 섞이고 Resend 월 한도를 쓴다.) 하루 100건(매체 합산), 부가 서비스(월 39,000원)는 베이직·스탠다드만 신청, 프리미엄부터 기본 포함.
  - 서버에서 받지 않는 것: 제목이 `(광고)`·`[광고]`·`(AD)`로 시작, 차단 도메인(`BLOCKED_SENDER_DOMAINS`), 제목에 `주간행사계획` 등(`NON_PRESS_TITLE_WORDS`). 한 통에 여러 건이 묶인 메일("취재지원자료 총N건")은 한 건씩 나눠 저장한다.
  - 편집장이 `/press/email`에서 **메일 섹션(분류)** 키워드와 섹션별 하루 건수(기본 5)를 정할 수 있다. 안 맞으면 "미분류".
- **첨부 정리**: 메일 첨부는 7일 지나고 기사로 쓰이지 않았으면 매일 새벽 4시에 지운다. 보도자료 글은 지우지 않고 숨기기만 한다 (수집기가 옛 글을 다시 가져오는 것을 막기 위해).

## 8. 이미 겪은 함정 (같은 실수 반복 금지)

- 서버 액션에서 버튼 `name/value`는 전달되지 않는다. 폼 데이터를 직접 `set`한다.
- `'use server'` 파일에서는 **async 함수만** export 할 수 있다. 상수·보조 함수는 `lib/`에 둔다.
- 한국어 정규식에서 `\b`는 한글에 통하지 않는다. 줄바꿈 금지는 CSS만으로 부족한 경우가 있어 보이지 않는 문자(U+2060)를 쓴다 (`keepCredit`).
- Postgres 정규식 반복 `{n,m}`은 최대 255. 임시 테이블 생성 SQL은 확인 창이 떠서 막힐 수 있으니 임시 테이블 없이 조회한다.
- 메일·첨부 글은 `\s` 사이에 공백이 끼는 PDF 추출이 흔하다 ("1 0 : 3 0"). 일정표 같은 자료는 기사 재료가 아니다.
- 지자체 사이트 일부(종로·중랑)는 우리 서버 접속을 막는다. 본문을 못 읽는 출처는 품질 판정에서 사라진다.
- 큰 파일을 올릴 때 네트워크가 끊겨 `fetch failed`가 날 수 있다. 같은 명령을 다시 실행하면 이미 올라간 파일은 건너뛴다.
- 사용자가 화면 이미지를 주면 그 화면이 **편집기 화면인지, 공개 사이트인지, 편집국 기사 보기인지** 먼저 구분한다 (같은 본문도 모양이 다르다).
