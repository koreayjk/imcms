# 새 언론사 개통 작업서 (운영팀·개통 전담 대화용)

이 문서는 새 언론사를 개통하고 시작용 기사를 AI로 써 줄 때의 순서와 규칙입니다. 다른 일(요금·청구, 메일 수신, 안내 영상, iOS 앱 심사)은 이 문서 범위 밖이고 건드리지 않습니다.

## 0. 일하는 방식

- 데이터베이스(Supabase)에는 직접 접속하지 못합니다. 모든 변경은 **SQL 파일**로 만들어 대표님이 Supabase SQL 에디터에서 실행합니다. 파일은 여러 번 실행해도 되게(같은 제목은 건너뛰기 등) 만듭니다.
- 코드·SQL·사진은 저장소에 두고, push 전에 항상 `git pull --rebase origin <작업 브랜치>` 후 push합니다. 같은 파일을 다른 대화와 동시에 고치지 않습니다 (특히 `CLAUDE.md`, `lib/pricing.ts`, `lib/onboarding-guide.ts`).
- 답은 한국어로 합니다. 새 SQL이 생기면 **파일 이름과 실행 순서**를 대표님께 분명히 알려 줍니다.

## 1. 개통 흐름 (고객이 보는 8단계 = `lib/onboarding-guide.ts`, 운영팀 체크 = `lib/launch-checklist.ts`)

1. 신청 접수·상담 (고객상담 화면, `/admin/leads`)
2. 편집국·홈페이지 개설과 초대: 매체를 만들면 "오픈 준비 중" 화면이 보이고, 발행인에게 초대 메일을 보낸다
3. 도메인 연결 (DNS)
4. 로고·색·법정 표기·섹션 정리 (`/admin/outlets/<id>/site`, 섹션은 `supabase/<이름>-sections.sql` 패턴)
5. 기존 기사·사진 옮기기 (또는 새로 시작하는 매체는 **시작용 기사 준비**) — 이전은 `docs/migration-runbook.md`
6. 사용법 안내: 고객센터 이용안내(영상 14편), 기사 작성 가이드
7. 정식 오픈과 검색 등록: 첫 청구서 발행(오픈 전)·납부 확인 → "오픈 준비 중" 끄기 → 검색 노출 켜기 → 서치어드바이저·서치콘솔
   - 오픈 직후 구글이 예전 robots.txt(오픈 준비 중에는 전부 막음)를 기억하고 있어, 서치콘솔 URL 검사에서 "robots.txt에 의해 차단됨", 사이트맵 "가져올 수 없음"이 하루쯤 남을 수 있다. 서버 robots.txt가 `Allow: /`인지 확인한 뒤: 서치콘솔 설정 → robots.txt 보고서 → 재크롤링 요청 → 사이트맵 삭제 후 다시 제출 → URL 검사 "색인 생성 요청". 이미 막힌 상태로 제출한 사이트맵은 오픈 뒤에 다시 낸다.
   - 지자체·협력기관 로고 띠가 필요한 매체: 홈페이지 설정(운영팀) → 로고 띠 → "지자체 불러오기"에서 광역·시·군·구를 골라 넣는다(이름표 + 시청 홈페이지 주소). 공식 로고(CI)는 줄마다 '로고 바꾸기'. 공식 로고를 "수원시.png"처럼 이름으로 한꺼번에 올렸다면 "주소 자동 채우기". 데이터는 `lib/local-gov.ts`, 이름표는 `public/sites/gov/`.
8. 오픈 후 1주 점검

진행 체크는 고객이 보는 **개통 현황** 화면(`/admin/onboarding/<매체>`)의 체크 항목으로 한다. 고객이 남긴 코멘트에는 같은 화면에서 답한다.

## 2. 시작용 기사를 AI로 쓸 때 (새로 시작하는 매체)

본보기: `supabase/seed-articles/newstoday-*.sql`, 사진 `public/sites/newstoday/photos/`.

- **기자명은 그 매체 편집장 이름** (`articles.byline`). 'IM뉴스룸'·'편집국'·'관리자'로 두지 않는다. 본문 첫머리 표기도 `[매체이름=편집장이름 기자]`. 편집장 계정이 있으면 `author_id`도 그 계정. 이름을 모르면 만들기 전에 묻는다. (이미 올라간 기사는 `supabase/fix-starter-byline.sql`의 매체·편집장 두 줄만 고쳐 실행)
- 상태는 **승인 대기(in_review)**. 바로 발행하지 않는다. 고객이 읽고 승인·수정·삭제한다. 사설·칼럼·인터뷰 같은 취재·의견 기사는 **초안(작성 중)** 까지만.
- 근거는 **정부·공공기관 보도자료**를 바탕으로 새로 쓴 글. 문장을 그대로 베끼지 않고, 확인되지 않은 사실을 만들지 않는다. 인용·숫자·날짜는 원문 기준.
- 기사마다 **AI 메모(`ai_notes`)** 에 남긴다: `확인할 점`(원문에 없어서 뺀 것, 발행 시점에 달라질 수 있는 것), `원문 주소`, `이용 조건`(공공누리 유형, 사진 라이선스).
- **AI 활용 사실은 기사에 표시**한다 (고객 개통 현황에도 그렇게 안내함).
- **모든 기사에 사진을 넣는다** (대표님 지시. 사진 없는 기사는 만들지 않는다). 받은 사진은 모두 눈으로 확인하고, 일반인 얼굴이 크게 나오면 흐리게 하거나 잘라 쓰고 캡션에 그 사실을 적는다.
- 위키미디어 공용 사진은 960px·500px 썸네일 주소로 받는다(원본 주소와 큰 썸네일은 요청 제한에 자주 걸린다). 요청 헤더에 이메일 등 개인정보를 넣지 않는다.
- 사진은 공개 라이선스(공공누리 1유형, 위키미디어 공용 CC 등)만. 자료사진이면 캡션에 촬영 시기·자료사진임을 밝히고, 사람 얼굴·번호판·특정 시설이 의도치 않게 지목되는지 확인. 파일은 `public/sites/<매체>/photos/`에 `webp`로.
- 쓰기 전에 `lib/writing-guide.ts`(기사 작성 가이드, 네이버 뉴스제휴 운영평가 기준)를 읽고 따른다: 바이라인, 제목 규칙, 보도자료 섹션 표기, 중복 기사, 사진 출처, 광고성·대가성 표현 금지.
- SQL은 같은 제목이면 건너뛰게(`where not exists`) 만들고, 맨 아래에 확인용 `select`를 적어 둔다.
- 업체 이름(경쟁 프로그램)을 기사·홍보 문구에 쓰지 않는다.

## 3. 자주 쓰는 확인

- 매체가 "오픈 준비 중"인지: 홈페이지 설정 → 오픈 준비 중 (이게 켜져 있으면 외부에서는 안내 화면만 보인다)
- 미리보기: 개통 현황의 "홈페이지 미리보기" 링크 (`?preview_outlet=<매체ID>`)
- 요금제·메일 수신 한도·추가 매체 요금은 다른 대화 담당. 필요하면 대표님께 알려 준다.

## 부가 서비스: 보도자료 메일 자동 수신 (월 39,000원)
- 프리미엄·엔터프라이즈는 기본 포함. 베이직·스탠다드는 신청한 매체만 (신청 전 메일 3통 무료 체험).
- 고객이 신청하면 고객센터에 "부가 서비스 신청" 요청이 들어온다 → 총관리자가 편집국 → 보도자료 → 메일로 받기 맨 아래 목록에서 그 매체의 **부가 서비스** 버튼을 켠다. 켠 날부터 쓸 수 있고, 켠 달은 남은 일수를 일할로 계산해 다음 달 청구서에 붙고 그다음부터 매월 39,000원이 붙는다(1년 결제 매체도 매월).
- 개통 때 고객이 원하면 같이 안내하고 바로 켠다. 요금 합의 없이 켜지 않는다. SQL: `supabase/press-email-addon.sql`.
